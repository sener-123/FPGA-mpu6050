# FPGA_imu — FPGA 读取 MPU6050 并解算姿态（PGL22G 开发板）

用 FPGA（Verilog）通过 I2C 读取 MPU6050 的三轴加速度与角速度，实时解算出欧拉角
（roll / pitch / yaw），并通过板载 USB 转串口打印。

```
FPGA_imu/
├── rtl/
│   ├── i2c_master.v       通用 I2C 主机控制器（可复用，与芯片无关）
│   ├── mpu6050_driver.v   MPU6050 初始化 + 500Hz 周期采集（例化 i2c_master）
│   ├── cordic.v           16级流水线 CORDIC 向量模式（atan2 + 开方）
│   ├── quaternion_ahrs.v  四元数姿态引擎（Mahony 互补滤波，逐帧迭代）
│   ├── attitude_calc.v    姿态解算（零偏校准 + 四元数 + 3×cordic 欧拉角）
│   ├── uart_tx.v          UART 发送器（115200 8N1）
│   └── mpu6050_top.v      顶层：例化全部模块 + FireWater 协议帧格式化
├── pds/
│   ├── pgl22g.adc         物理约束：引脚位置/电平标准（PDS）
│   └── pgl22g.fdc         时序约束：50MHz 时钟（PDS）
└── README.md
```

模块依赖关系（低耦合，逐层封装）：

```
mpu6050_top
 ├── mpu6050_driver ── i2c_master
 ├── attitude_calc ── quaternion_ahrs + cordic ×3
 └── uart_tx
```

## 1. 功能

- 上电自动初始化：延时 100ms → WHO_AM_I(0x75) 校验 → 唤醒(0x6B=0x00) → 稳定 50ms → 配置寄存器
- 每 2ms 突发读 14 字节（0x3B~0x48），输出原始数据 + 帧同步脉冲（500Hz）
- **上电零偏自动校准**：复位后前 512 帧（约 1 秒）**任意角度保持静止**即可，以各轴
  max-min 变化幅度判定静止（晃动自动重试），锁定陀螺零偏（加速度不扣零偏、
  保留完整重力矢量），后续帧自动扣除——这是姿态精度的关键
- 解算三轴加速度（g）、角速度（°/s）、欧拉角 roll/pitch/yaw（°），全部 Q16.16 定点
- 串口每 100ms 打印一帧 FireWater 协议（VOFA+）CSV 数值流：9 通道（角度/加速度/角速度）
  逗号分隔，两位小数，`\r\n` 结尾
- 4 个 LED 指示系统状态（错误/心跳/初始化完成/校准完成）

## 2. 量程与配置

| 项目 | 配置 | 寄存器值 |
|---|---|---|
| 采样率 | 500 Hz（SMPLRT_DIV=1） | 0x19 = 0x01 |
| 低通滤波 | DLPF_CFG=1（加速度带宽 184Hz / 陀螺 188Hz） | 0x1A = 0x01 |
| 陀螺仪量程 | ±250 °/s，131 LSB/(°/s) | 0x1B = 0x00 |
| 加速度量程 | ±2g，16384 LSB/g | 0x1C = 0x00 |

## 3. 姿态算法

- **上电零偏校准**（复位后约 1 秒，**任意角度保持静止**即可，竖直/平放/斜放均可）：
  - 前 512 帧累加陀螺原始值取平均，同时跟踪各轴加速度 min/max 判定静止；
    晃动幅度超阈值（约 0.125g ≈ 3.6° 等效）自动清零重新累计，直到静止才锁定
    陀螺零偏——LED4 点亮才表示校准成功（曾用"水平度检查"要求放平，板子竖直放置时
    校准永不完成、零偏不扣、姿态漂移跳变，2026-09-28 改为静止检测）
  - **加速度不扣零偏、保留完整重力矢量**：曾按 512 帧均值扣除，会把校准时姿态的
    重力投影一并扣掉，板子回到校准姿态时 a≈0、四元数失去重力参考、姿态锁死
    （2026-09-28 上板实锤）。MPU6050 加速度零偏典型 <50mg，保留引入的静态倾角
    误差一般 <1°，模长/方向由四元数内部的加速度归一化保证
  - 校准期间输出保持 0，LED4 点亮后数据开始有效
  - 静止水平放置时：AX/AY ≈ 0.00（微小波动），**AZ ≈ +1.00 是重力加速度，
    属正常物理值**，不是零偏残留（显示为归一化值，放平 AZ=+1.00、
    竖直时重力显示在 AX/AY ≈ ±1.00 上）
- **四元数 Mahony 互补滤波**（`quaternion_ahrs.v`，每帧 2ms 迭代一次，约 132 个时钟，
  算法对照 x-io Technologies 的开源 MahonyAHRS.c 成熟实现逐项对齐；
  全部乘法串行复用同一个 64 位乘法器——PGL22G 只有 30 个 DSP，并行乘法会耗尽
  DSP 并把 LUT 撑爆，曾报 LUT 超限 19345/17536，串行化后大幅下降；
  **所有乘法操作数经 s64() 显式符号扩展为 64 位**——Verilog 乘法结果位宽 =
  两操作数位宽最大值（与结果寄存器宽度无关），32×32 写法先截断再扩位，
  曾致 dq 恒 0、|a|²=0、角度锁死/乱飘、加速度显示全 0（2026-09-28 修复））：
  - 四元数 Q16.15 定点（1.0=32768），初始为单位四元数（水平姿态），可连续跟踪
    任意 360° 姿态，无欧拉角奇点
  - 加速度 8 帧滑动平均低通（16ms 窗口，`attitude_calc.v` 内实现）+ 帧内归一化
    （a/=|a|，牛顿迭代求 1/√|a|²）：与标准实现一致，消除 |a| 偏差对修正幅度的影响
  - **加速度合理性门控**：|a| 超出 0.25g~2.25g 时跳过重力修正（只靠陀螺积分）——
    防止手持运动时的线性加速度把姿态拉歪（成熟实现的关键抗干扰手段）
  - 误差：`e = a × v`——归一化加速度 a 与四元数估计重力方向 v 的叉积
  - 角速度修正：`ωc = ω + Kp·e`（Kp=3753，与 MahonyAHRS.c 默认 twoKp=1.0 定标完全
    一致，即 0.5 rad/s 每弧度误差，时间常数约 2s；Kp 不宜再调大，否则静止抖动加剧）
  - 积分：`q += 0.5·dt·q⊗ωc`，模长修正 `q ← q·(3-|q|²)/2`（牛顿迭代一阶式，
    每帧残差约 1e-11，可忽略）
- 欧拉角由旋转矩阵元素经 3 个 CORDIC atan2 得到（全范围，无 ±90° 折叠）：
  - `roll  = atan2(R32, R33)`，范围 ±180°
  - `pitch = atan2(-R31, R33)`，范围 ±180°（板子翻过 90° 继续显示 90~180，
    倒扣时接近 180；旧式 acos/±90° 公式在 160° 倾斜时只会显示 20°）
  - `yaw   = atan2(R21, R11)`，范围 ±180°
- `yaw` 无绝对参考：MPU6050 没有磁力计，仅由陀螺 z 轴积分维持（零偏校准后
  漂移显著减小）。大角度翻转后 yaw 可能整体偏移——这是仅有重力参考时的物理限制

## 4. PDS 工程搭建（PGL22G 开发板）

1. 打开 PDS（Pango Design Suite），新建工程：
   - 器件选 **PGL22G**，封装 **MBG324**（手册 2-2 节：FPGA 型号 PGL22G-6CMBG324）
2. 添加设计文件：`rtl/` 下全部 **7** 个 .v 文件（含 `quaternion_ahrs.v`，
   漏掉它编译会报 "quaternion_ahrs is referenced to undefined module"）
3. 添加约束文件：`pds/pgl22g.adc`（物理约束）与 `pds/pgl22g.fdc`（时序约束）
4. 综合 → 布局布线 → 生成位流 → 下载（板载 JTAG，手册 3-10 节）
5. 若报 "IO is not enough" 之类的错误，确认：
   - 顶层设为 `mpu6050_top`
   - 未定义 `DEBUG_PORTS` 宏（见第 9 节，宏打开后端口数从 9 变 304，会超出 240 IO 上限）

## 5. PGL22G 引脚连接

### 5.1 板载资源（已固定，约束文件已配好）

| 信号 | 顶层端口 | FPGA 引脚 | 说明 |
|---|---|---|---|
| 50MHz 晶振 | `clk` | B5 | 板载，手册 2-3 节 |
| 复位按键 | `rst_n` | F10 | 板载，低有效，手册 2-7 节 |
| USB 转串口 | `uart_tx` | C10 | 板载 CP2102，手册 3-6 节 |
| LED1~LED4 | `led[3:0]` | U10/V10/U11/V11 | 板载，手册 3-13 节 |

### 5.2 MPU6050（GY-521 模块）接线 —— J8 排针

`i2c_scl`/`i2c_sda` 约束在 J8 排针第 35/36 脚，紧邻电源脚，接线最方便：

| GY-521 模块 | J8 排针 | FPGA 引脚 |
|---|---|---|
| VCC | 第 39 或 40 脚（+3.3V） | — |
| GND | 第 37 或 38 脚（GND） | — |
| SDA | 第 35 脚 | R18（`i2c_sda`） |
| SCL | 第 36 脚 | N14（`i2c_scl`） |

- 板载 I2C 总线（A15/B15）只连了 EEPROM、未引出排针，所以 MPU6050 接 J8 扩展口
- I2C 是开漏总线，**必须外接上拉电阻**；GY-521 模块自带 4.7kΩ 上拉，直接用即可。
  若用自制/裸片模块，需在 SDA、SCL 各接 4.7kΩ 电阻到 3.3V
- 换其他引脚接线时，只需修改 `pds/pgl22g.adc` 中 `i2c_scl`/`i2c_sda` 的
  `PAP_IO_LOC` 两行（J8 全部引脚定义见手册 3-9-2 节）

## 6. LED 状态指示

板载 LED 为低电平点亮，RTL 已按此极性适配，下表"点亮/熄灭"即肉眼所见状态：

| LED | 含义 |
|---|---|
| LED1 (U10) | 错误指示：点亮 = WHO_AM_I 校验失败或 I2C NACK |
| LED2 (V10) | 数据心跳：约 2Hz 闪烁 = 数据正常流动（校准完成后开始） |
| LED3 (U11) | 初始化完成：进入采样状态后点亮 |
| LED4 (V11) | 零偏校准完成：点亮 = 系统就绪（上电后任意姿态保持静止约 1 秒；晃动会一直重新校准，LED4 不亮，静止后自动完成） |

上电正常时序：LED1 灭 → 约 0.2s 后 LED3 亮 → 约 1 秒校准后 LED4 亮 → LED2 开始闪烁。

## 7. 串口输出格式（VOFA+ FireWater 协议）

板载 CP2102 的 USB 口直连电脑（需装 CP210x 驱动），串口助手设置：
波特率 115200、数据位 8、无校验、停止位 1。每 100ms 一帧 **FireWater 协议** CSV
数值流：9 个通道逗号分隔、`\r\n` 结尾，帧长可变（前导零与正号省略），示例：

```
0.00,-0.35,0.00,0.00,0.00,1.00,0.00,0.00,0.00
```

- 通道顺序：`roll, pitch, yaw, AX, AY, AZ, GX, GY, GZ`（角度单位 °、加速度单位 g、
  角速度单位 °/s，均两位小数）
- VOFA+ 中协议引擎选择 **FireWater**（数据源里选对串口后通道自动按 ch0~ch8 命名）
- 水平静止时：`0.00,0.00,*,0.00,0.00,1.00,0.00,0.00,0.00`（AZ ≈ +1.00 是重力，
  属正常；yaw 缓慢漂移属无磁力计的正常现象）

## 8. 上板验证步骤

1. 按第 4 节建好 PDS 工程，按第 5 节接好 MPU6050，下载位流
2. **复位后保持板子静止约 1 秒（任意角度均可）**，等待零偏校准完成（LED4 点亮）
3. 打开串口助手（115200）：
   - 静止平放：`R/P ≈ 0.00`（零偏校准后静态误差一般 ±0.1° 以内），`AZ ≈ +1.00`
   - 绕 X 轴翻转：roll 跟随变化（范围 ±180°，倒扣时 ≈180）
   - 绕 Y 轴翻转：pitch 跟随变化（范围 ±180° 全量程，翻过 90° 继续增大）
   - 绕 Z 轴旋转：yaw 变化（零偏已消除，静止后仅缓慢温漂）
4. 若串口无输出，对照第 6 节看 LED：
   - LED1 亮（错误）：检查 SDA/SCL 是否接反、模块供电是否 3.3V
   - LED3 灭：初始化未完成，检查 I2C 接线
   - LED4 灭且 LED2 不闪：校准未完成（约 1 秒，期间保持静止）

### 8.1 串口乱码排查

若串口助手收到乱码、且每行长度不一（正常时每帧为 9 个数值的 CSV 行，长度 42~61 字符），
先用板载 4 个 LED 判断 FPGA 内部是否在正常工作，再检查信号链路：

**第一步：看 LED，判断 FPGA 内部状态（最省事的分水岭）**

| LED 现象 | 结论 | 下一步 |
|---|---|---|
| LED3、LED4 亮，LED2 约 2Hz 闪烁 | 初始化完成、数据在流动，**FPGA 侧完全正常** | 问题 100% 在外接链路，见第二步 |
| LED3、LED4 亮，LED2 不闪 | 初始化完成但无数据（可能 I2C 有瞬时错误） | 见 LED1 是否亮：亮=I2C 接线问题 |
| 全部 LED 不亮 | **设计没有跑起来** | 查 `clk`：电平标准必须 LVCMOS33/3.3V（晶振是 3.3V 输出），若 PDS 器件配置里 Bank L0 电压被设成 1.2V 请改回 3.3V；查 `rst_n` 电平（松开复位键后应为高） |
| LED1 常亮 | WHO_AM_I 校验失败（SDA/SCL 接反、MPU6050 没接或供电不对） | 不影响串口：此时串口仍会打印全 0 的数据帧，若串口连全 0 帧都没有，问题仍在串口链路 |

**第二步：外接 USB-TTL 模块链路自查（按概率排序）**

1. **共地**：模块 GND 必须接 J8 的 GND（第 1 或 37/38 脚）。没有公共地，信号没有参考，
   表现正是"乱码 + 长度不一致"——这是外接模块最常见的坑
2. **交叉接线**：FPGA 的 `uart_tx`（J8-3 = T11）是发送端，必须接模块丝印 **RXD** 脚
   （FPGA TX → 模块 RX，交叉接法）。接到模块的 TXD 脚上就收不到正确数据
3. **模块自环测试**：把模块的 TXD、RXD 两根线短接，在串口助手发任意数据，
   能原样回显 = 模块、驱动、USB 线均正常；不能回显 = 模块/驱动问题
4. 换杜邦线、重新插紧（接触不良极常见）
5. 模块供电：3.3V 模块不要接 J8 的 +5V；5V 模块供电正常但注意别把 TXD 接回 FPGA
6. 若以上都正常，用示波器/逻辑分析仪量 T11：应能看到 3.3V 方波，
   位宽约 86.8µs（115200bps），每 100ms 一帧突发

**板载 CP2102 串口（不接外接模块时）**：`uart_tx` 必须约束到 C10（板载 CP2102 的
RXD 输入脚，手册 3-6-2 表）。约束到其他引脚时 C10 悬空 → CP2102 把噪声当数据发给
电脑，表现同样为乱码。另外确认插的是 USB-UART 口（CP2102）而非 USB2.0 口（FT232H），
VOFA+ 协议引擎选 **FireWater**（不要选 JustFloat 等私有协议；若只看原始文本可选
"普通协议"），编码 UTF-8/GBK 均可。

## 9. 二次开发接口

### 9.1 DEBUG_PORTS 宏（宽调试端口）

默认顶层只占用 **9 个 IO**。需要把解算结果引到引脚上观察时（例如接逻辑分析仪），
在 PDS 工程设置中定义宏 `DEBUG_PORTS`（或命令行 `+define+DEBUG_PORTS`），
顶层将额外引出 12 个端口：

| 端口 | 位宽 | 含义 |
|---|---|---|
| `accel_x_g / accel_y_g / accel_z_g` | [31:0] | 加速度，Q16.16，单位 g |
| `gyro_x_dps / gyro_y_dps / gyro_z_dps` | [31:0] | 角速度，Q16.16，单位 °/s |
| `roll_deg / pitch_deg / yaw_deg` | [31:0] | 姿态角，Q16.16，单位 ° |
| `data_valid` | 1 | 数据有效脉冲（约 500Hz） |
| `error[1:0]` | 2 | 00=正常 01=WHO_AM_I失败 10=I2C NACK |
| `state_dbg[7:0]` | 8 | 驱动状态机状态 |

> ⚠️ 打开宏后端口总数约 304 个，**超出 PGL22G-6CMBG324 的 240 IO 上限**，
> 布局布线会报错（这就是之前 "IO is not enough" 错误的原因）。
> 这些端口只适合引出个别几个信号，且必须在 .adc 中自行添加引脚约束。
> 更推荐用 PDS 的在线逻辑分析仪（DebugCore）观察内部信号，无需占用 IO。

Q16.16 换算：实际值 = 端口值(有符号) ÷ 65536。

### 9.2 模块级复用

- `i2c_master.v`：通用 I2C 主机，与 MPU6050 无关，可直接复用到任何 I2C 芯片
- `uart_tx.v`：通用串口发送器，`tx_start` 脉冲触发、`tx_busy` 握手
- `attitude_calc.v` / `quaternion_ahrs.v` / `cordic.v`：纯逻辑封装，四元数模块
  输入输出均为已标定的物理量，可直接换成 EKF/Madgwick 等其他算法

## 10. 已知限制

- yaw 漂移：无磁力计，仅积分角速度；大角度翻转后 yaw 可能整体偏移（重力参考
  无法约束航向，这是四元数互补滤波的固有特性，属正常现象）
- 姿态解算在加速度计有持续线性加速度时精度下降（修正项按重力参考设计，
  适合手持/静止/慢速场景）
- 加速度零偏未扣除（优先保留重力矢量）：加速度计零偏较大（>50mg）时姿态可能有
  1~3° 的静态倾角误差；如需更高精度可再添加"方向感知"的零偏估计
- 四元数初始姿态为"单位四元数"（相当于假设水平），若上电时板子已倾斜，
  重力修正项会在约 2~3 秒内把姿态收敛到真实值（收敛期间角度渐近趋近，属正常）
